## P1 — Dead code with a behavioral side effect (fix, don't just delete)

### A1. System prompt / long-term-memory facts never reach the LLM
- **Where:** `agent/orchestrator.py` (`_system_prompt` built at lines 80,
  118; never read afterwards) vs `agent/workers.py:33-36` (workers build
  their own system prompts) and `agent/supervisor.py` (router has its own).
- **Why it matters:** since the supervisor refactor, `config.SYSTEM_PROMPT`,
  `config.DEMO_SCHEMA_DESCRIPTION`, and the LTM facts loaded in
  `start_session`/`load_session` are computed and **discarded**. Docs
  (v1.6.1 release notes: "facts are injected into future system prompts")
  and the memory-inspector UI imply facts shape future answers — they don't.
  This is dead code *claiming* to do work: the schema description the model
  is supposed to see is never sent, so routing/SQL quality relies entirely
  on the task text.
- **Impact of fixing:** facts and schema actually influence worker answers
  (documented behavior restored); also lets SYSTEM_PROMPT rules ("report
  tool failures honestly") apply again.
- **Risk:** changes model behavior — some scripted tests assert exact worker
  system prompts; a test pass is needed. Distillation prompt interception in
  FakeLLMClient is unaffected.
- **Recommendation:** pass `_system_prompt` (or `_ltm_context` + schema)
  through `SupervisorAgent` into `WorkerBase.run`'s system message. ~15 lines
  + test updates. Decide deliberately: this is a behavior change, not cleanup.
